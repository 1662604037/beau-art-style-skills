# 图片艺术转化迭代器

这是 `beau-art-style-transfer` 的进化层，不替代主技能。它把真实生成中的用户反馈变成可追踪、可验证、可回滚的最小改进。

## 核心边界

- 默认只记录事实、归类反馈、生成提案和回归测试；不要直接覆盖主技能。
- 只有用户明确说“应用、写回、确认更新、以后按这个规则”或同等语义时，才修改主技能。
- 不把某一张图的主题偏好硬编码成永久规则；只有可迁移到多类图片的问题才升级。
- 不把工具报错、图片未显示和画面质量不满意混成同一种失败。
- 没有实际看到图片时，不能声称检查过主体、构图、文字或画风，标记为 `manual_review`。

## 触发范围

直接使用本技能的请求包括：

- 用户要求复盘某次艺术转化；
- 用户说“把这次经验记住”“以后不要再犯”“写进技能”“优化这个图片技能”；
- 用户指出主体跑偏、画风漂移、颜色过艳、墨色太重、构图改变、水印残留等可复用问题；
- 用户要求比较新旧版本规则或验证一次改动是否真的改善。

如果用户只是继续修改当前图片，不要启动规则沉淀，回到 `beau-art-style-transfer` 的预览迭代流程。

## 反馈记录

在当前技能包的工作状态目录中维护：

```text

```

## 迭代流程

### 1. 提取事实并归因

先区分：

- 用户明确指出的画面问题；
- 实际查看到的图像事实；
- 工具是否成功生成；
- 是否只是界面展示问题；
- 主技能已有规则是否覆盖该问题。

工具返回失败或图片无法显示，属于技术/展示层问题；图片生成成功但主体、画风或构图不符合要求，属于视觉质量问题。对外报告时使用清晰的标签：`视觉质量复核`、`技术/传输恢复`、`展示层恢复`。

### 2. 判断是否值得升级

只有满足以下条件之一，才生成永久规则候选：

- 用户明确要求写入技能；
- 同类问题至少出现两次；
- 问题违反主技能已有质量边界；
- 问题会稳定导致错误重试、错误报告或可重复的视觉失败。

只针对当前图片的偏好，例如“这次树叶再少一点”，先记录为案例，不自动改主技能。

### 3. 形成最小提案

每轮只处理一个主要问题簇，并写明：

```text
问题：现有规则为什么不够用
证据：哪些反馈、图片检查或工具结果支持判断
假设：加入什么最小规则可以减少问题
影响：会改变哪些步骤，可能误伤什么场景
不变项：主体、风格、画幅、水印处理和输入参考图规则中哪些必须保留
```

优先修改主技能的“生成前约束”“生成后检查”“反馈翻译”“重试归因”或“报告格式”，不要无理由重写整个工作流。

### 4. 生成回归用例

每个提案至少包含：

- 一个正例：源图主体复杂、用户要求风格化但主体必须可识别；
- 一个反例：用户明确要求自由再创作，不能误判为主体保真失败；
- 若提案涉及失败处理，再加一个“工具成功但界面未显示”的展示层用例。

艺术质量依然需要人工查看；不要把“画得好不好”伪装成精确自动分数。

### 5. 临时验证与安全写回

验证以下内容：

- YAML frontmatter 与触发描述有效；
- 技术失败、视觉失败和展示层问题分流；
- 不会把一次性偏好升级成永久规则；
- 不会削弱主体保真、去水印、参考图安全或用户确认门槛；
- 提案只修改目标规则，且能通过快照回滚。

用户明确确认应用后：

1. 重新读取主技能并检查是否被外部修改；
2. 创建应用前快照；
3. 只应用最小补丁；
4. 更新 `CHANGELOG.md`；
5. 重跑结构检查和回归用例；
6. 报告已应用的规则、未改变的规则和回滚路径。

## 用户报告格式

```text
本轮状态：已记录 / 已生成提案 / 验证通过待确认 / 已应用 / 已阻止
问题簇：
证据：
拟改动：
回归结果：通过 X，失败 Y，需人工复核 Z
未改变：
文件：
下一步：等待确认 / 继续收集反馈 / 回滚
```

## 失败恢复

- 状态文件损坏：保留原文件，创建带时间戳的恢复副本；
- 回归结果矛盾：标记 `manual_review`，不自动写回；
- 主技能哈希已变化：停止应用并展示差异；
- 反馈不足以泛化：只记录案例，不生成永久规则；
- 连续两轮没有改善：停止继续堆叠限制，回到用户质量目标和单变量迭代。
