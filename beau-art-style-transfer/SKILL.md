# 图片艺术转化

把一张真实图片变成艺术作品时，先保护用户真正关心的主体，再改变媒介、笔触和氛围。输出重点不是一段漂亮提示词，而是一张用户能看、能比较、能继续修改的图。

## 触发与输入路由

触发于以下请求：

- “把这张照片变成水墨画/油画/版画/插画”等风格转换请求；
- 用户上传图片并说“艺术化、重绘、画风化、像某种艺术媒介”；
- 用户提供一张风格参考图，要求把另一张图片做成相似的视觉语言；
- 用户对上一轮结果说“再淡一点、建筑要更像、减少黑色、保留构图”等。

先判断输入：

1. **源图**：要被转换的照片或图片。若已有本地路径，先用 `view_image` 检查；若只有对话附件，使用最近的图片作为输入。
2. **风格描述**：用户说出的媒介、气质、色彩、笔触和时代感。
3. **风格参考图**（可选）：只用来理解视觉语言，不复制其中的具体人物、文字、标志或独特构图。
4. **约束**：用户明确要求保留或改变的主体、构图、比例、文字、水印、背景和颜色。

如果风格完全没有说明，只问一个最关键的问题；不要让用户填写技术表格。若已有足够信息，直接生成第一张预览。

## 默认工作流

### 1. 先确定“保留什么”和“改变什么”

用一句话复述工作约束：

- 保留：主体身份/建筑轮廓/人物姿态/主要构图/用户明确要求的物件；
- 改变：艺术媒介、笔触、色彩、光线、纸张或画布质感；
- 清除：用户要求去掉的水印、角标、小字、杂讯和原图版权标记；
- 不新增：没有被用户要求的文字、签名、印章、logo、人物或叙事元素。

当用户只说“主体保留即可”时，保留主体的可识别性和主要位置，但允许简化周边细节、背景和次要物件。对于建筑主体，还要锁定建筑的时代类型与关键结构语言：古建筑保留屋檐、层级或构件关系；现代建筑保留曲面、开口、幕墙网格或连续壳体。水墨化不能把现代建筑误画成传统建筑，也不能让古建筑失去原有结构身份。

### 2. 生成第一张预览

默认使用内置 `image_gen` 工具，编辑类请求优先使用源图作为输入；存在风格参考图时，再附上最多一张最相关的参考图。不要在普通请求中使用 CLI 或要求用户提供 API key。

提示词采用以下结构，内容按实际任务填写，不要机械补充未被用户要求的情节：

```text
Use case: style-transfer
Asset type: <预览图或最终艺术图>
Primary request: <把源图转换成什么艺术媒介>
Input images: Image 1 = 源图; Image 2 = 可选的风格参考图
Scene/backdrop: <保留或重新组织的环境>
Subject: <主体及其必须保持的识别特征>
Style/medium: <媒介、笔触、表面质感>
Composition/framing: <画幅、主体位置、裁切和视角约束>
Lighting/mood: <光线和情绪>
Color palette: <色彩范围和饱和度>
Materials/textures: <纸张、画布、颗粒、干湿笔触>
Text (verbatim): "<只在用户明确要求文字时填写>"
Constraints: <必须保留、必须去除、不得新增>
Avoid: <与目标相冲突的风格、结构错误、文字和水印>
```

提示词要明确“只改艺术媒介和指定变量，其他约束保持不变”。对于有文字或水印的源图，明确写出“去除原有文字/水印，不新增任何文字”，但不要把原图文字当作需要重绘的内容。

### 3. 展示和检查

生成后先实际查看图片，不要只根据工具返回的成功状态判断质量。默认向用户展示：

1. 原图；
2. 当前预览结果；
3. 一句“本轮改变了什么”；
4. 一句可直接使用的反馈示例，例如“墨色再淡一点，但建筑轮廓不要变”。

检查四类不变量：

- **主体**：用户要保留的建筑、人物、产品或景物仍能一眼识别；
- **构图**：视角、主体位置、裁切和画幅符合约束；
- **艺术语言**：媒介和笔触明显，颜色与气质没有漂移；
- **清洁度**：没有原水印、伪文字、无意新增的签名、logo、边框或印章。

若生成成功但界面没有显示，先检查工具返回的图像字段或保存路径；不要把展示层问题误判成生成失败。

### 4. 按反馈迭代

把用户的自然语言反馈翻译成“本轮只改一件主要事情”的编辑指令。例如：

- “墨色太重” → 降低黑色覆盖和线条密度，保留构图、主体细节和淡彩范围；
- “建筑不够像” → 提高建筑结构保真，锁定屋檐、层级、轮廓和视角，不改变目标媒介；
- “颜色太艳” → 降低饱和度和对比度，保留纸张质感与主体位置；
- “太像照片” → 增加可见笔触、洗染和纸张留白，但不要改变主体结构；
- “背景太乱” → 简化次要背景元素，给主体留出呼吸空间，不新增内容。

每轮只改一个主要变量；同时保留用户已经认可的变量。除非用户明确要求，不要在同一轮同时换画风、换构图、换色板和换主体细节。

### 5. 定稿

只有用户说“可以、定稿、就这样、完成”或同等语义时，才把当前版本标记为最终版本。定稿时报告：

- 最终图像；
- 采用的风格描述；
- 保留与改变的关键规则；
- 是否去除了水印/文字；
- 生成文件路径（若用户要求保存文件）。

如果用户只是说“再试一版”，继续预览循环，不提前宣称完成。

## 当前风格预设

需要选择风格时，读取 `references/style-presets.md`。本次已确认的首个预设是 `light-ink-color-wash`：水墨淡彩、主体可识别、周边可简化、去除水印、跟随原图画幅。

参考图只约束媒介和视觉语言，不复制参考图中的具体人物、文字、logo、签名或独特场景。

## 失败恢复

- 图像输入传输失败：减少输入图数量，保留源图；若仍失败，改用完整的文字约束并说明是无参考图恢复。
- 视觉质量不达标：只重试一次，并只强化失败的约束；说明重试是“视觉质量复核重试”。
- 工具或网络失败：明确报告“技术/传输失败”，不要伪称已生成。
- 用户反馈仍然模糊：只追问一个最影响结果的问题，例如“你更想要更淡的墨色，还是更少的建筑细节？”

## 安全与边界

- 不把一次性偏好默认为永久风格规则，除非用户在迭代技能中明确确认写入。
- 不复制在世艺术家的独特签名、署名或可识别的具体作品；可以使用媒介、时代、技法和一般视觉特征来描述目标。
- 不保留或重绘用户要求删除的水印、角标和文字。
- 不声称“完全保留原图”或“质量通过”，除非已实际查看并确认相应不变量。
